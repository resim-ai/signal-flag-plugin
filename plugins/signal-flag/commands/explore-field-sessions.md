Run this plugin command directly. Load `explore-field-sessions` with `get_skill` from the configured Signal Flag MCP server, using `$ARGUMENTS` or the current request. The served skill owns registration, summary inspection, replay, signal interpretation and evaluation. Load `author-session-metrics-build` only for missing emission/runtime capability, and the existing `author-metrics-config` for chart editing, grouped review and reusable publication.

Use the requested environment/account; when the request refers to an open page, match the connected tab. The default server name is `signal-flag`; preserve existing account mappings. Verify `whoami` before project work, reusing identity while the context is unchanged. Explicit session IDs, links and S3 folders do not require browser discovery. Recommend the recording-producing robot checkout for domain investigation while continuing supported work without it.

Registered-session metadata, folder inventory, identity and Foxglove links need no reader installation. Before MCAP summary inspection, run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/setup_reader.py" --check`. If the runtime is missing, use `/signal-flag:setup-reader` for explicit setup and use its returned Python path. The served workflow provides a summary-only API compatible with the installed bundle; do not assume a newer CLI. Interactive message sampling is outside this workflow's supported capabilities. Never use the full-traversal `inspect` command for discovery or download an MCAP as a fallback. Missing runtime or blocked range transport remains an inspection limit.

For a new build, follow `author-session-metrics-build` to keep editable source and real synthetic SDK tests in the customer's maintained directory. Prepare and test before seeking publication confirmation when no AWS writes are needed. Follow the publication section of `explore-field-sessions` before any AWS writes: verify the effective identity used by the publication tools, show caller account/role, credential source, region and full destination (including its account), and obtain explicit confirmation. Reuse it only while that identity and destination remain unchanged. The agent builds/pushes through the authorized AWS MCP capabilities and verifies the remote digest.

Evaluation approval is separate from registry confirmation. Show the exact sessions, build/version and metrics set and obtain explicit human approval of that request in the conversation before launching. Honor the client's permission prompt when present. Permission mode, automatic tool acceptance and an agent-written matching `confirm` string are not human approval. Do not claim an unseen prompt was approved. Reconcile uncertain submissions; never replay automatically or alter permission settings.

If the server or skill is unavailable, report the configured environment and the connection/authentication or missing-skill problem. Do not invent tools or reconstruct an unavailable workflow from memory. A saved browser edit is authoritative; verify its actual definition and preserve the selected historical evaluation scope. Publishing reusable configuration remains a separate requested operation.
